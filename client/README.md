# GoreeCloud Notify native client

This directory contains the first-party Flutter client shared by the Linux and Android delivery targets.

## Current acceptance scope

- Native login against the GoreeCloud Notify human-session API.
- Session cookie and CSRF token persisted through platform secure storage.
- Authenticated inbox retrieval and real-time SSE delivery.
- Read/unread and acknowledgement actions.
- Privacy-redacted local operating-system alerts while the client is running outside the foreground.
- Android notification permission requested only after explicit user action from the inbox; startup and sign-in do not trigger the permission prompt.
- System light/dark appearance through the shared GoreeCloud application identity.
- Linux `.deb` and Android APK acceptance artifacts produced by GitHub Actions.

The client is not a WebView and does not embed the web application as its primary runtime.

## Security boundary

The client never stores the user's password after login. It stores only the opaque server session cookie and CSRF token in the platform secure-storage provider. Notification previews generated by the native client are redacted and instruct the user to open GoreeCloud Notify rather than exposing message content on the lock screen.

## Android background-delivery boundary

The initial acceptance build maintains the real-time SSE connection while the Flutter process remains running. Persistent Android background delivery after process termination is a separate production-acceptance gate and must be validated before ntfy can be retired as the phone's independent alert path. This boundary is deliberate; the project must not claim ntfy-equivalent background delivery until Android lifecycle testing proves it.

## Build targets

GitHub Actions pins Flutter 3.47.0 and generates platform scaffolding at build time. The canonical client source remains small and reviewable in this directory.

- Linux: `goreecloud-notify_<version>_amd64.deb`
- Android: `goreecloud-notify-android-acceptance.apk`

The Android acceptance artifact is installable but is not a production-signed Store release. Production Android signing material must remain outside source control.
